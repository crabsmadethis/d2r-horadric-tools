# D2S Research Status

This page tracks public `.d2s` save-format findings that are useful for future
tooling work. Keep it concise: answered questions become findings, and remaining
questions must include a proof method.

For release sequencing, see `docs/d2s-version-roadmap.md`.

## Confirmed Findings

| Area | Public finding | Tooling consequence |
| --- | --- | --- |
| Follower payload count | `lf<u16:follower_count>` is followed by exactly `count * 116` payload bytes for known bound-demon saves. | Reject count/payload mismatches in the scanner and writers. |
| Bound demon count | D2R accepts one known Warlock bound-demon payload and rejects tested count-2 bound-demon saves. | Public chargen should support at most one bound demon. |
| Embedded `gf` bytes | `payload[92:94] == b"gf"` inside a bound-demon payload is data, not a section marker. | Do not split the save at that embedded byte pair. |
| Volatile demon bytes | Bound-demon payload bytes `+89..+91` may change on save/exit. | Treat that slice as runtime data; do not author it. |
| Authorable demon fields | Template-derived edits to `monster_hcidx`, bind level, and the seven MonUMod bytes can persist. A random monster seed override was stripped back to `follower_count=0` on save/exit. | Keep seed preservation separate from authored seed overrides. |
| Bound-demon visible affixes | Clearing the MonUMod vector removes visible properties. Natural over-cap evidence shows the persisted affix vector is seven bytes at `+80..+86`; the old `+85/+86` model-candidate bytes are overflow affix slots. On Black Lancer, copying natural source-affix `bitfields_64_79` activated Cursed and Stone Skin from the same persisted affix tuple; copying the post-`gf` tail did not change that result. Fanaticism alone did not activate, Aura Enchanted alone did not display an aura label in the tested context, but Fanaticism plus Aura Enchanted displayed Aura Enchanted with Fanaticism. A generated seven-slot Black Lancer package displayed all authored labels plus an active Fanaticism aura and saved back with the follower payload unchanged. | Treat the seven MonUMod bytes, monster identity/model, hard skill level, payload `+52`, and `bitfields_64_79` context as separate persisted inputs. Model Fanaticism as a source/aura-flavor affix that needs Aura Enchanted to expose the visible aura path; keep Bind Demon threshold derivation limited to the skill table. |
| Bind Demon level behavior | Fresh natural binds confirm the skill table thresholds: level 5 writes Extra Strong, level 10 writes Extra Strong plus Extra Fast, level 15 adds Spectral Hit, and level 20 adds Aura Enchanted. Source monster affixes can also carry through. Payload `+52` stayed `7` for completed binds and is not effective skill level. | Chargen derives skill-granted affixes from effective Bind Demon level and keeps source affixes separate in YAML. |
| Same-model one-slice demon mutations | In a Fallen same-model control, D2R accepted a zeroed `+89..+91` volatile slice and rewrote it on save/exit, accepted and preserved both donor and zeroed variants of `+64..+79`, accepted a donor `+95..+115` tail while canonicalizing part of it, rewrote zeroed `+24..+31`, preserved nonzero `+44..+51`, and rewrote `+88` to `00`. Changing `+94` from `06` to `00` joined once but saved back as a scanner-invalid variable-length follower block. Fully zeroing `+95..+115` froze/failed to join. Narrower tail tests showed `+96/+97`, `+104/+105/+106`, and `+109/+111/+112` are accepted-rewritten, `+101/+102` can join but saves as an invalid 106-byte follower payload, zeroing `+115` freezes during join, and zeroing `+114` loads without a demon then strips the follower on save. | Treat `+89..+91`, `+24..+31`, `+88`, `+96/+97`, `+104/+105/+106`, and `+109/+111/+112` as D2R-rewritten in same-model Fallen probes; keep `+94 == 06`; do not author `+101/+102`; preserve the final `+114/+115` bytes as `f0 1f` for same-model Fallen until another original capture proves otherwise; keep `+64..+79` optional for same-model Fallen only. |
| Model-companion generated probes | Changing only `monster_hcidx` inside the Fallen family is not sufficient. A swap from `20` to `19` produced a visible demon but saved back stripped to `follower_count=0`; a swap from `20` to `21` preserved a valid 116-byte payload but did not show a visible demon. A MonStats/MonStats2 comparison for `19/20/21` found the selected MonStats2 body/animation fields effectively identical, while MonStats differs in transform level, AI params, speed, levels, combat stats, and elemental flavor. Clean cross-model corpus stratification between `20` and `347` originally highlighted `+85/+86`, but those are now decoded as affix overflow slots; remaining candidate companion offsets include `+24`, `+28`, `+95`, `+100`, `+103`, `+105`, `+110`, `+111`, and `+112`. Council Member target `347` now has three live-positive variants: candidate-offset copy, reduced preserved-offset copy, and hcIdx-only. A follow-up value `723` probe loaded as DarkArcher and saved cleanly, proving payload monster ids are zero-based MonStats row indexes and not the `*hcIdx` column. Corrected value `724` joined as Black Lancer and saved back cleanly. Natural-context and generated seven-slot Black Lancer probes proved skill affixes, source bitfield context, and the Fanaticism/Aura pairing. | Model identity behavior is target-dependent. Same-family Fallen swaps still need companion bytes or original captures, but Council Member `347` and Black Lancer `724` can be generated from this Fallen control with hcIdx only. Use `tools/d2s_monster_model_compare.py` for row-index table comparisons, `tools/d2s_demon_payload_corpus.py` for `model_candidate_offsets`, and `tools/d2s_forge_demon_payload.py --copy-offsets-from` for controlled model-companion probes. Player-facing YAML should stay template-derived until template-free synthesis proves all required companion bytes. |
| Cross-class followers | A structurally valid borrowed follower block can load on a non-Warlock save but is stripped back to `follower_count=0` on save/exit. | Do not expose cross-class follower payloads as normal chargen behavior. |
| Iron Golem block | Iron Golem data lives in `kf` before `lf` as a single variable-length item payload. | Generated golems should use item encoding and must not write multiple golem payloads. |
| `jf` before merc items | The `jf` corpse marker can be present or absent before merc `JM` while the tail remains parseable. | Preserve the existing marker shape unless a targeted edit proves a safe normalization. |

## Open Questions

| Question | Why it matters | Next proof method |
| --- | --- | --- |
| Bound-demon model identity | `monster_hcidx` can persist, but hcIdx-only edits can be visible-then-stripped or structurally preserved without a visible demon. The first Fallen-family table comparison points more toward MonStats-derived gameplay/model state than MonStats2 body animation state. | Compare original same-family natural-bind payloads against monster-id overrides while holding seed, bind metadata, and affix bytes constant. Also compare nearby MonStats rows before promoting another generated model-swap probe. |
| Template-free bound-demon synthesis | A template-derived payload can be edited, but generating all 116 follower bytes for arbitrary demons requires knowing which unknown slices are fixed, generated, model-derived, or volatile. | Follow the synthesis proof ladder in `docs/bound-demon-chargen-roadmap.md`: corpus classification, same-model natural binds, one-slice mutations, same-family swaps, cross-family swaps, then a synthetic initializer. |
| Merc status at `0xA7..0xA8` | The field has more observed values than the writer currently understands. | Group local saves by hireling id, difficulty, merc gear count, and progression. |
| Broader Iron Golem item families | Normal and magic generated golems are supported, but more item families need canonicalization-aware expectations. | Add synthetic fixture tests first; use manual validation only for item families tests cannot prove. |
| Rare item naming | Rare and crafted items carry first-name and last-name row ids separate from stat affixes. Chargen can auto-select numeric ids, but symbolic rare-name YAML, import round-tripping, and D2R display validation are not yet locked down. | Add fixture-backed tests that resolve RarePrefix/RareSuffix names by type, import rare name ids back to YAML, and manually validate one deterministic rare per major item class. |
| Socketed jewels through chargen | Socketed simple rune fillers are supported, but non-simple socket fillers such as magic or rare jewels are documented as unsafe because full-save validation has produced failed joins. Jewel stats are therefore not normal socket-filler authoring yet. | Build a synthetic socketed parent with one jewel filler in staging, scan parent/filler counts and bit offsets, then live validate. Until proven, merge intended jewel stats onto the parent item instead of writing jewel sub-items. |
| Shared stash support | Current item placement targets character inventory, cube, personal stash, and merc-stash workflows inside `.d2s`. Shared stash lives outside the character save and has different blast radius. | Decode shared-stash files from disposable Offline profiles into public-safe structure notes, then create a separate backup/edit/scan/restore ladder before any writer support. |
| Expansion quest and misc items | Item bases for organs, keys, essences, Worldstone shards, Uber Ancient materials, tokens, and similar misc items exist, and some normal-misc fixture builds scan. Stack counts, special quest flags, usability, shared-stash placement, and live acceptance are still not broadly proven. | Expand synthetic fixtures by item family, verify quantity/stack behavior where applicable, then manually validate one representative per family in a disposable Offline save. |

## Recording Rules

- Put durable byte-layout facts in `docs/d2s_format.md`.
- Put user-facing manual procedures in `docs/manual-save-validation.md`.
- Do not commit raw saves, local paths, or session diaries.
- Do not leave an answered question in this file as "open"; move it to the
  confirmed table with the limitation that still matters.
